# heaptide v0.1.0

**Released:** 2026-10-09 · **Commit:** tag `v0.1.0` · **Previous:** first release

## What it does

heaptide finds leaks in CPU, GPU (HIP and Mojo) and Python programs in one pass, without
rebuilding them. On an 8-thread malloc benchmark it runs 4.1x faster than heaptrack with 6.5x less
added memory. On every planted leak in its test suite, its direct/indirect split matches
LeakSanitizer's. It also sees HIP device and pinned host memory, Mojo's GPU buffers included,
which no other leak tool we know of covers on ROCm.

```
heaptide run [--gpu] [--py] [--every MS] [--out DIR] -- CMD...      default DIR .work/heaptide
heaptide report DIR [--json] [--top N] [--supp FILE] [--fail-on any|leaks|growth|none]
```

## Highlights

- One tool for CPU, GPU (HIP, Mojo) and Python leaks, no rebuild of the target.
- Direct/indirect/reachable split equal to LeakSanitizer on every planted leak, with thread stacks,
  registers and linker blocks as roots.
- GROWTH verdict that skips a long setup instead of failing it.
- 4.1x faster and 6.5x less added memory than heaptrack on an 8-thread malloc benchmark.
- Absolute growth limit (`--growth-limit MIB`); works without ROCm (symbolizer on PATH, or module names).

## Changes

### Added
- First public release: `heaptide run` / `heaptide report`, modes `--gpu`, `--py`, `--every`,
  report options `--json`, `--top`, `--supp`, `--fail-on`, `--growth-limit`.
- `skills/heaptide/SKILL.md`: an agent skill for the find, fix, prove loop on `report --json`.
- `report --json` carries `growth_window_bytes`, `window_from_s`, and per-leak `indirect` and `blocks`; `--supp` now filters its leak list.
- `tests/run.sh --cpu` and a CPU-only GitHub Actions workflow (ubuntu-24.04).
- Prebuilt `heaptide-<version>-linux-x86_64.tar.gz` (glibc 2.34+, Mojo runtime bundled), attached to each release by `.github/workflows/release.yml`; built by `tools/package.sh`.
- Docs: `docs/how-it-works.md`, `docs/file-format.md`, `docs/testing.md`, `examples/demo.c`, `CONTRIBUTING.md`, `SECURITY.md`.

## Known limits

- No interior-pointer scan (residue: HIP runtime 2.9 KiB, Mojo 96 B).
- GPU and pinned host blocks are never scanned; unfreed at exit means direct leak.
- Linux x86-64 only; GPU paths tested on one machine (RX 7900 XTX, ROCm 7.2), CPU paths also on Ubuntu 24.04.
- The GitHub workflows (cpu, release) have not run on GitHub yet; their steps passed in local ubuntu:24.04 containers.
- Full list: README, "Where it is wrong".

## Upgrade / run

```
# prebuilt: tar xzf heaptide-v0.1.0-linux-x86_64.tar.gz, then the same commands inside it
./build.sh
./heaptide run -- ./your-program && ./heaptide report .work/heaptide
```
