# heaptide v0.1.1

**Released:** 2026-10-09 · **Commit:** tag `v0.1.1` · **Previous:** [v0.1.0](v0.1.0.md)

## What it does

heaptide finds leaks in CPU, GPU (HIP and Mojo) and Python programs in one pass, without
rebuilding them. On an 8-thread malloc benchmark it runs 4.1x faster than heaptrack with 6.5x less
added memory. On every planted leak in its test suite, its direct/indirect split matches
LeakSanitizer's. It also sees HIP device and pinned host memory, Mojo's GPU buffers included,
which no other leak tool we know of covers on ROCm.

```
heaptide run [--gpu] [--py] [--py-depth N] [--every MS] [--out DIR] -- CMD...      default DIR .work/heaptide
heaptide report DIR [--json] [--top N] [--supp FILE] [--fail-on any|leaks|growth|none]
```

## Highlights

- Fewer false leaks: a pointer into a block's middle keeps it alive, as in LeakSanitizer.
  CPython's ~170 KiB of exit "leaks" are gone.
- Stripped system libraries resolve to function and source line through debuginfod.
- Reserve-then-commit allocators (Go, JVM, custom arenas) are counted as `mprotect` commits them.
- Nine bugs from two external reviews fixed, among them a hidden leak after a failed `realloc`
  and a deadlock at exit.
- `--py-depth N` shows each Python site as its call chain.

## Changes

### Added
- `--py-depth N`: tracemalloc keeps N frames; PYTHON groups by call chain (`a.py:4 <- a.py:6`).
- debuginfod lookup in the report: a module without debug info is swapped for its debug file by
  build-id (elfutils' cache, else fetched from `DEBUGINFOD_URLS`). ROCm's llvm-symbolizer has no
  debuginfod of its own.
- `mprotect` and `madvise` hooks: committed parts of anonymous `PROT_NONE` reservations are
  `mmap` blocks; `mprotect(PROT_NONE)` and `madvise(MADV_DONTNEED|MADV_FREE)` decommit.
### Changed
- Reachability follows interior pointers. Residue: HIP runtime 2.9 KiB -> 216 B direct + 48 B
  indirect; Mojo 96 B direct -> 1.2 KiB indirect; CPython ~170 KiB -> 0.
- `--py` sites skip `tracemalloc_*` frames (heaptide's own instrumentation).
- README: PEAK under `--gpu` is the unpooled allocator's; leak findings are unchanged.
### Fixed
- The prebuilt report was compiled for the build machine's CPU and crashed (illegal instruction) on
  older x86-64; it now targets x86-64-v2.
- A forked child that exits without exec no longer repeats the parent's leaks.
- Failed `realloc` kept the block with size 0 (leak hidden); old size and site are restored.
- Exit deadlocked when a parked thread held the loader lock.
- PEAK missed allocations still in a thread's batch at exit.
- Leak totals and suppressions stopped at 1000 sites.
- Unknown `--fail-on` value silently disabled failing; now exit 2.
- Notes and errors printed to stdout before `--json` output; now stderr.
- A quote in the report directory broke symbolizing; non-PIE executables lost source lines.
- `build.sh` exited 0 after a failed Mojo build, keeping the old binary.
- Release tarball lacked `py/run.py`, so packaged `--py` could not run.
- `RTLD_NEXT` through the `dlsym` hook depended on the compiler emitting a tail call (wrong at
  `-O0`); now forced with `musttail`.

## Known limits

- Interior pointers can hide a leak when a stray word falls inside it (same trade as LSan).
- Exit scan up to ~3x slower when the heap is dense with interior pointers.
- First report with debuginfod downloads debug files (104 MB for libpython + numpy + libc).
- Pages re-touched after `madvise` without a new `mprotect`, and `mremap` of a reservation, are not seen.
- A thread that takes the loader lock over and over at exit can delay exit (no deadlock).
- Full list: README, "Where it is wrong".

## Upgrade / run

```
./build.sh
./heaptide run -- ./your-program && ./heaptide report .work/heaptide
```
Optional for debuginfod: `readelf`, `curl`.
