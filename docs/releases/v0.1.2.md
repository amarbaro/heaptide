# heaptide v0.1.2

**Released:** 2026-10-09 · **Commit:** `695dfd7` · **Previous:** [v0.1.1](v0.1.1.md)

## What it does

heaptide finds leaks in CPU, GPU (HIP and Mojo) and Python programs in one pass, without
rebuilding them. On an 8-thread malloc benchmark it runs 12x faster than heaptrack with 6.7x less
added memory. On every planted leak in its test suite, its direct/indirect split matches
LeakSanitizer's. It also sees HIP device and pinned host memory, Mojo's GPU buffers included,
which no other leak tool we know of covers on ROCm.

```
heaptide run [--gpu] [--py] [--py-depth N] [--every MS] [--snapshot-every S] [--out DIR] -- CMD...
heaptide snapshot DIR
heaptide report DIR [--json] [--top N] [--supp FILE] [--fail-on any|leaks|growth|none]
```

## Highlights

- Long-running services: SIGTERM / Ctrl-C still write the report, and `heaptide snapshot DIR`
  (or `--snapshot-every S`) reports on a process that keeps running.
- Exit scan 2-3x faster on large heaps (10M blocks: 48 s -> 16.6 s).
- malloc overhead down 3x (8-thread bench 0.38 -> 0.13 s, now 12x faster than heaptrack): a
  per-thread cache of call-stack ids skips the shared lock.
- Two sites can no longer merge on a hash collision.
- Reserve-then-commit allocators: pages reused after `madvise`, and reservations moved by
  `mremap`, are counted.
- Snapshots barely stall the program: it pauses only to fork (10M live blocks: 15 ms).
- Crashes (SIGSEGV, SIGBUS, SIGFPE, SIGILL, SIGABRT) write the report too.

## Changes

### Added
- Report on SIGTERM, SIGINT, SIGHUP (only where the program kept the default handler); the
  process still dies of the signal.
- Snapshots of a running process: `heaptide snapshot DIR`, `--snapshot-every S`. Threads are
  parked only to fork; the child scans the copy-on-write image (raw `clone`, invisible to the
  program's `wait`), falling back to an in-place scan if the fork fails. 1M live blocks: 3-7 ms
  pause (147 ms in place); 10M: 15 ms (1851 ms). A snapshot is skipped if a thread cannot be parked.
- Crash reports: SEGV/BUS/FPE/ILL/ABRT where the program kept the default; best effort, 10 s
  limit; the process still dies of the signal. Stack overflows included: the main thread and
  every thread that allocates get a signal stack.
- Snapshot rows (PEAK, HOTSPOTS, block counts) are exact: the fork flushes every thread's batched
  counters in its copy.
- `--py`: the PYTHON section is written on SIGTERM/SIGHUP (runner's own handler, then the shim's
  exported `heaptide_final()`) and next to every snapshot (a watcher thread). A stop signal during
  interpreter startup is held until the runner is ready.
- `bench/snap_pause.c`: the longest stall a program sees during a snapshot.
### Changed
- Per-thread 64-entry stack-id cache: a known site takes no lock (alloc_bench 0.38 -> 0.13 s
  median, RSS unchanged at 12.5 MB).
- `.bin` header field 6 is a flags word; bit 0 = leaked block counts follow the samples. The
  report reads older files (block counts then show live blocks).
- Report: a damaged or truncated `.bin`, a missing option value, an unknown option or an
  out-of-range value is exit 2. The launcher checks option values too.
- Built-in suppression for glibc's `_dlerror_run` buffer (libc releases it at exit behind
  malloc's back).
- Under `ulimit -v` the shim's arenas shrink to a quarter of the limit; if they still cannot be
  mapped it records nothing and says so.
- Exit scan: three-level branchless search, 16 words at a time with each level prefetched.
- Report files are written as `.tmp` and renamed (a reader never sees half a file).
### Fixed
- Stack-hash collisions merged sites; a 32-bit check hash now separates them.
- Pages returned with `madvise(DONTNEED/FREE)` and reused by plain writes were not counted.
- A reservation moved or grown by `mremap` lost its later commits.
- Fixes from an external review (each reproduced first, each with a test in `tests/c_edge.c`,
  `tests/hip_mock.c` or the report checks):
  - `realloc(p, 0)` freed `p` but heaptide restored it: a false leak, and a crash at exit when
    the block was mmap-backed.
  - The madvise-returned range list could overflow its array (64k entries allocated, 1M allowed).
  - `ulimit -v 1G`: a tiny program crashed under heaptide.
  - `mremap` of a reservation's middle lost the moved part; `MREMAP_FIXED` double-counted the
    replaced mapping; the fifth argument was read without `MREMAP_FIXED`.
  - PEAK missed other threads' batched updates.
  - A failed `hipFree`/`hipHostFree`/`hipFreeAsync` dropped a block that was still live.
  - `dlsym("hipMalloc")` answered non-NULL without any HIP library loaded.
  - The report crashed on a truncated `.bin` and passed a header with an impossible count.
  - `--json` did not escape backslashes or control characters.
  - A leak's block count included reachable blocks at the same site.
  - A program path containing a space lost its source lines.
  - `report --top` without a value crashed; `reallocarray` overflow left `errno` at 0.
- A final report no longer races a snapshot child still writing the same files.
- The madvise residency check called `mincore` once per resident run instead of once per range.

## Known limits

- SIGKILL and the OOM killer write no report; use `--snapshot-every`.
- A stack overflow writes a report only in the main thread or a thread that has allocated.
- A snapshot's fork can cost up to the heap's size in memory while the program rewrites pages.
- The in-place fallback is tested only as a non-root user (`prlimit --nproc` does not bind root).
- Full list: README, "Where it is wrong".
