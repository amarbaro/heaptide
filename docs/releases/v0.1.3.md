# heaptide v0.1.3

**Released:** 2026-10-11 · **Commit:** `092d9f9` · **Previous:** [v0.1.2](v0.1.2.md)

## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
heaptide finds leaks in CPU, GPU (HIP and Mojo) and Python programs in one pass, without
rebuilding them. On an 8-thread malloc benchmark it runs 12x faster than heaptrack with 6.7x less
added memory. On every planted leak in its test suite, its direct/indirect split matches
LeakSanitizer's. It also sees HIP device and pinned host memory, Mojo's GPU buffers included,
which no other leak tool we know of covers on ROCm.

```
heaptide run [--gpu] [--py] [--py-depth N] [--every MS] [--snapshot-every S] [--out DIR] -- CMD...
heaptide snapshot DIR
heaptide report DIR [--json] [--top N] [--supp FILE] [--fail-on any|leaks|growth|none]
```

## Highlights

- `--py` profiles packages: `heaptide run --py -- python -m pkg.module` works.
- Python snapshots dump 3.9x faster (benchmark: 104 s -> 27 s, same 3.86 GB peak).
- A report now carries its own memory maps inside the `.bin`, so it can never be paired with
  another run's maps.
- Runs on ASan-built programs (gcc, or clang `-shared-libsan`): both tools work at once.
- Fork-heavy threaded programs: no more absurd negative peak sites in the children.

## Changes

### Added
- `--py` accepts `python -m pkg.module` (runs through `runpy.run_module`).
- ASan-built programs (shared ASan runtime): the launcher turns off ASan's link-order check, and
  the `dlsym` hook no longer crashes when ASan's init calls it from the loader. Static ASan (clang's
  default) cannot be watched: heaptide warns instead of writing an empty report.
- Unnamed frames print their module offset, `[libX.so+0x1a2b]`, stable per build (Mojo's runtime
  ships no internal symbols).
### Changed
- Python snapshot: statistics are grouped first, then heaptide's own rows dropped (was a trace
  filter over every block): 104.1 s -> 26.9 s on `bench/py_bench.py`, 3.86 GB peak both.
- Report ranks sites with one sort instead of n linear passes: 65536 sites 0.32 -> 0.22 s
  (RSS 74 -> 80 MB); text and `--json` output byte-identical.
- File format: maps text stored inside the `.bin` (header flag bit 1, field 7 = length). Old files
  with a separate `.maps` still report. See `docs/file-format.md`.
### Fixed
- Fork children no longer show a site with ~18 EB peak (a negative count): the peak snapshot
  clamps a site briefly negative from another thread's batched free. fork() also holds the tables
  across the copy and folds the gone threads' batched counts into the child.
- A snapshot parks threads with a real-time signal the program left free (from `SIGRTMAX-2`
  down), instead of replacing the program's own `SIGRTMAX-2` handler for good.
- Report writes retried when interrupted by a signal (`EINTR`).
- Tests check heaptide itself: its report binary for leaks (`self`), and the shim's own memory
  staying flat under a steady program (`c_steady`, RSS and VmSize).
- Test `py_snapshot` / `py_term` flake: the snapshot could fire before the planted allocation; the
  test now waits for the program's own `held` marker.
