## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
heaptide finds leaks in CPU, GPU (HIP and Mojo) and Python programs in one pass, without
rebuilding them. On an 8-thread malloc benchmark it runs 12x faster than heaptrack with 6.7x less
added memory. On every planted leak in its test suite, its direct/indirect split matches
LeakSanitizer's. It also sees HIP device and pinned host memory, Mojo's GPU buffers included,
which no other leak tool we know of covers on ROCm.

```
heaptide run [--gpu] [--py] [--py-depth N] [--every MS] [--snapshot-every S] [--out DIR] -- CMD...
heaptide snapshot DIR
heaptide report DIR [--json] [--top N] [--supp FILE] [--fail-on any|leaks|growth|none]
heaptide attach PID [--out DIR]  ·  heaptide detach DIR  ·  heaptide diff BASE NEW
```

## Highlights

- `--py` names, in Python, the object that holds each top site's memory (`bytearray << Box.data[0] << __main__.keep['a']`).
- Child processes each get a named report section; `--no-children` and `--only NAME` pick which are traced.
- Attach no longer crashes a program whose thread maps memory before its first malloc.

## Changes

### Added
- `--py` holder chains for the top Python sites and the biggest GPU tensors.
- Report sections named by process; `--no-children`, `--only NAME[,NAME]`.
- Every traced process answers `heaptide snapshot`; `snapshot --label NAME` keeps a set in `DIR/NAME`.
- `--py` runs `python -c CODE`.
- `--gpu` also turns PyTorch's caching allocator off, so each tensor is its own block.
- NOTICE names the owner and contact.
### Changed
- Device allocations keep their whole stack, so the Python line under torch's C++ shows with `--py`.
- Mojo runtime frames are kept out of LEAKS/PEAK; a debuginfod miss is noted once per module.
- No transparent huge pages for the shim's sparse arenas (less resident memory).
### Fixed
- Attached, a thread whose first hooked call is `mmap` crashed the program at exit when its mapping held a guard page.
- A forked child's GPU timeline carried the parent's samples.
- `--py`: a script ending in `sys.exit()` or an error lost what its globals held from the PYTHON section.
- `--gpu-timeline frag` called HIP after HIP's teardown at exit (torch exited 134).
- glibc's free-chunk bins could hold a leaked block and hide it.

## Known limits

<!-- Honest list: slow paths, unsupported cases, flaky upstreams, anything UNVERIFIED. -->
- Same platform limits as v0.1.5 (Linux x86_64; GPU tested on gfx1100 only). A process that leaves through `_exit()` (dash, Ubuntu's `sh`) writes no report. Found, not fixed: realloc of a pointer from the shim's startup buffer may read past it; an in-place snapshot that runs out of memory after marking leaves marks set.
