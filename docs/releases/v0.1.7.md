# heaptide v0.1.7

**Released:** 2026-10-30 · **Commit:** `1b575b8` · **Previous:** [v0.1.6](v0.1.6.md)

## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
heaptide finds leaks in CPU, GPU (HIP and Mojo) and Python programs in one pass, without
rebuilding them. On an 8-thread malloc benchmark it runs 12x faster than heaptrack with 6.7x less
added memory. On every planted leak in its test suite, its direct/indirect split matches
LeakSanitizer's. It also sees HIP device and pinned host memory, Mojo's GPU buffers included,
which no other leak tool we know of covers on ROCm.

```
heaptide run [--gpu] [--py] [--py-depth N] [--every MS] [--snapshot-every S] [--out DIR] -- CMD...
heaptide snapshot DIR
heaptide report DIR [--json] [--top N] [--supp FILE] [--fail-on any|leaks|growth|none]
heaptide attach PID [--out DIR]  ·  heaptide detach DIR  ·  heaptide diff BASE NEW
```

## Highlights

<!-- 1 to 5 bullets a user would notice. Lead with the benefit, not the implementation. -->
- Runs on older Linux: on glibc before 2.34 (Ubuntu 20.04, RHEL 8) the shim crashed every program at start.
- ROCm runs report much less noise: the runtime's one-time allocations are dropped by default, and `report` no longer waits on debuginfod (a ROCm run: 90 s to 0.4 s).
- `--py` names Python frames in native stacks again when the report is built with Mojo 1.2.0.
- A run with more distinct call stacks than the table holds now says so instead of losing them silently.

## Changes

### Added
- `report/default.supp`: the ROCm runtime's one-time allocations, applied by default; `--no-default-supp` turns it off. The report prints one `suppressed N B in K blocks` line; JSON has `suppressed_bytes` and `suppressed_blocks`.
- A `WARN pid=N stack table full` line at report time when new stacks found no row.
### Changed
- `report` symbolizes without llvm-symbolizer's own debuginfod lookups.
- The shim's spinlock pauses, and yields every 64 spins, so a preempted holder does not stall its waiters.
- Tested toolchain: Mojo `1.3.0.dev2026102914` with max `26.8.0.dev2026102914`.
### Fixed
- glibc before 2.34: `dlsym` was looked up only as `GLIBC_2.34`; the shim then called through NULL.
- The stack counter could pass the table limit and, on a long run, wrap onto ids in use and overwrite their rows.
- Built with Mojo 1.2.0, the report lost every `py::` frame (the compiler skips a `for ... else` branch at -O3).

## Known limits

<!-- Honest list: slow paths, unsupported cases, flaky upstreams, anything UNVERIFIED. -->
- Spinlock change: speed not measured.
- The table-full warning is on stderr only; the `.bin` file and the report do not carry the drop count.
- On glibc 2.31 only the shim was run (`c_leak`); the full suite was not run there.
- Same platform limits as v0.1.6 (Linux x86_64; GPU tested on gfx1100 only).
