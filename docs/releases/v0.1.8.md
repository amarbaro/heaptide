# heaptide v0.1.8

**Released:** 2026-11-03 · **Commit:** `999c0ae` · **Previous:** [v0.1.7](v0.1.7.md)

## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.
     3 to 6 lines: what it is, who uses it, where it runs (URL/port/binary), how to start it. -->
heaptide finds leaks in CPU, GPU (HIP and Mojo) and Python programs in one pass, without
rebuilding them. On an 8-thread malloc benchmark it runs 12x faster than heaptrack with 6.7x less
added memory. On every planted leak in its test suite, its direct/indirect split matches
LeakSanitizer's. It also sees HIP device and pinned host memory, Mojo's GPU buffers included,
which no other leak tool we know of covers on ROCm.

```
heaptide run [--gpu] [--py] [--py-depth N] [--every MS] [--snapshot-every S] [--out DIR] -- CMD...
heaptide snapshot DIR
heaptide report DIR [--json] [--top N] [--supp FILE] [--fail-on any|leaks|growth|none]
heaptide attach PID [--out DIR]  ·  heaptide detach DIR  ·  heaptide diff BASE NEW
```

## Highlights

<!-- 1 to 5 bullets a user would notice. Lead with the benefit, not the implementation. -->
- GPU and pinned host memory a program still holds is no longer reported as leaked: ComfyUI Z-Image went from 10.88 GiB of false leaks to 0.
- A process killed by SIGKILL or the OOM killer, or that leaves through `_exit()`, still gets a report.
- `--py` on a big heap no longer risks an OOM, and its overhead is halved (30M blocks: +2.31 GB to +1.12 GB).
- Three CLI traps fixed: a reused `--out` DIR mixed runs, `python3 -u -c` broke `--py`, and a malformed `diff` exited 0.

## Changes

### Added
- A report after SIGKILL, the OOM killer or `_exit()`: tables live in `/dev/shm` and the wrapper or `heaptide report` writes them afterwards (`ENDED WITHOUT A REPORT`, no leak scan).
- Attached reports state the most they can miss (`before attach:`, `mallinfo2`).
- A full stack table is in the saved file and the report: `WARN stack table full: N allocations`, JSON `dropped_allocations`, flag bit 7 in `docs/file-format.md`.
- `HT_NO_UNWIND` bench knob: the hook cost split is measured.
### Changed
- GPU and pinned host blocks referenced from outside the HIP runtime are HELD, with a holder, not LEAKS.
- GROWTH: the window may start up to 3/4 into the run, so a late model load in a short run is not growth.
- `--py` live table capped at 1/8 of available memory (`HEAPTIDE_PY_MEM`), PYTHON warns about untracked blocks; hash tables grow at 3/4 load.
- `report` prints the target process first.
- `--out DIR` is cleared of an earlier run's heaptide files at start; other files stay.
- The agent skill is a router `SKILL.md` plus `references/` and a tested `scripts/ht.sh`.
- `build.sh` uses the repo's `.venv` mojo before the one on PATH.
### Fixed
- A snapshot of a busy traced process could be unreadable (`report` and `diff` crashed): header and sections read the shared counters at different times. Seen on ComfyUI.
- A reused `--out` DIR mixed earlier runs into the report (a `c_leak` run then `/usr/bin/true` still showed 100005 B leaked).
- `--py python3 -u -c ...` ran `-u` as a script path; interpreter options now stay the interpreter's.
- `diff` with a trailing `--fail-on` or an unknown option exited 0 with the default policy; now exit 2.
